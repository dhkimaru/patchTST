## 2. 이전 프로젝트에서 가져오는 교훈

- **유지:** run 단위 분할, train-only scaler, 시간 끊김에서 구간 분할, persistence 기준선, 물리 단위 MAE, 파일 단위 paired 통계.
- **버림:** Phase마다 복사한 runner(16.5k줄), 실험을 실행하지 않는 통제용 자동화(16.4k줄), `Literal`로 잠긴 하이퍼파라미터, 고정 seed 42/43/44.
- **다시 확인할 결론:**
  - VG11 없이 추정한 virtual sensing(VB1 MAE 16.8)은 PressAct 원값보다도 7배 나빴다. RevIN이 절대 레벨을 지우는 설계 결함 때문이므로 G1에서 다시 한다.
  - seed 편차(0.0145)가 많은 ablation 차이보다 컸다. 결론은 seed 여러 개와 run 단위 교차검증으로 낸다.
  - 모든 Phase가 Test로 비교·선택했다. 이번에는 test run을 봉인한다.
- **속도:** 이전에는 RTX 4090에서 run 하나 학습에 2~5시간이 걸렸고 GPU 메모리는 약 150 MB만 썼다.
  데이터 전체(약 0.35 GB)를 GPU에 올리고 batch를 키우면 수 배 이상 빨라질 것으로 본다(측정 필요). 많이 시도하려면 이것이 먼저다.

## 3. 평가 설계 원칙

- **분할:** run 단위. 시간 순서를 지키는 holdout(마지막 run들 = test, 봉인)과, 학습/검증 run 안에서의 run 단위 K-fold.
- **G1 공정성:** 대상 센서의 복사본(VG11 ↔ PressAct ↔ AUXMon_VG11처럼 |r|≥0.999인 쌍)은 대상과 함께 입력에서 뺀다.
  "센서 그룹 통째로 없음" 시나리오(예: 압력계 전부)를 따로 평가한다.
- **G1 지표:**
  - 대상별 물리 단위 MAE, 공정 구간(ALD 사이클)과 대기·승온 구간을 나눈 MAE
  - 기준선 대비 개선율. 기준선은 선형회귀, 직전값, 같은 step의 평균
- **G2:**
  - run이 70개뿐이라 단순 모델(선형·트리)과 요약 특성이 기준선이다. 지표는 leave-run-out 오차와 run 간 변동 대비 설명력이다.
  - 이상 run(1·2·55·57)은 따로 표시하고 기본 학습에서 뺀다.
- **G3:**
  - 비교 대상: 같은 개수의 무작위 컬럼 세트, 데이터 기반 선택 세트(학습 run만으로 계산).
  - 성공 기준(개선 폭, 통계 검정)은 실험 전에 이 문서에 먼저 적는다.

## 3.1 G1 가상 센서 — 이상 감지 관점의 진행 방식 (2026-10-23 결정)

사용자 방향: 특정 센서 하나가 아니라 **유의미한 파라미터부터** 시작한다. 이상 감지에서는 중요한 파라미터의 변화를
미리 아는 것이 핵심이다. 따라서 가상 센서는 두 가지로 쓴다.

1. **지금 값 추정(nowcast)**
   - 같은 시점의 다른 센서와 레시피 맥락으로 대상 값을 추정한다.
   - 실측 − 추정 = **이상 점수**: 센서는 정상인데 공정이 이상하거나, 센서 자체가 이상할 때 커진다.
   - 센서를 달지 않은 경우의 대체값으로도 쓴다.
2. **변화 예측(forecast)**: 대상 파라미터의 수 초~수십 초 뒤 값을 예측한다(이전 프로젝트의 VG11 10/20/30초 과제를 일반화).

대상 선정은 `ald-analyze-params` 결과(ALD 사이클 구간, 학습 run 템플릿, 검증 run 평가)를 따른다.
기준은 세 가지다.

- **레시피 설명력 R²**: 레시피 순서만으로 설명되는 비율. 0.99 이상이면 템플릿 비교로 충분하다(F.PWR 등).
- **계열 제외 교차 추정 R²**: 같은 계열 센서(같은 zone 열전대, 압력계 전부, 같은 가스 라인)를 모두 빼고
  다른 센서로 잔차를 설명하는 비율. "센서를 달지 않은" 경우다.
- **run 간 변동**: run별 잔차 평균이 run마다 얼마나 움직이는지. 장비 상태 변화나 VM과 연결될 수 있다.

1차 후보 17개(계열별 대표, 중요도 A·B + 압력·APC·RF 매칭):

| 묶음 | 컬럼 | 관찰 (검증 run, 선형) |
| --- | --- | --- |
| 온도 5 zone | TempAct_U/CU/C/CL/L | 레시피로 거의 설명 안 됨(R² 0.1~0.2). 같은 zone 열전대를 빼도 인접 zone으로 0.94~0.98 |
| 챔버 압력 | VG11 | 레시피 0.95. 다른 압력계가 있으면 0.95, 압력계를 모두 빼면 0.13 → 비선형·시계열 모델이 필요한 핵심 대상 |
| 배기 | APCValveMon | 레시피 0.92, 교차 0.33 |
| RF 매칭·반사 | MFCMon_L.POS, MFCMon_P.POS, AUXMon_R.PWR | L.POS는 run 간 변동이 큼(0.23). 챔버 상태 지표 후보 |
| 가스 유량 | MFCMon_DCS, MFCMon_NH3, MFCMon_N2-1/3/4 | 레시피 0.95~0.99, 남은 잔차 일부만 추정 가능(0.2~0.6) |
| 밸브 | ValveAct_29, ValveAct_89 | 타이밍 편차가 다른 밸브로 설명됨(0.94~0.95) |

다음 실험(R3)은 이 후보마다 다음을 같은 분할(split_v2)로 비교한다.

- 모델: 기준선(템플릿, 선형) → 트리(LightGBM) → 시계열(PatchTST·iTransformer 등)
- 입력 세트 3종: 전체 / 계열 제외 / 핵심(A) 파라미터만 (G3)
