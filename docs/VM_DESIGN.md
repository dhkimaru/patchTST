# 두께 예측(VM) 설계

2026-11-20 시작. 가상 센서 16개의 최종 구성이 정해져(1~654차) 두 번째 과제인 두께 예측으로 넘어간다.
이 문서는 설계와 단계별 판정 기준을 적고, 결과는 README '결과 (Daily 갱신)'와 `docs/RESULTS_LOG.md`에 쌓는다.

## 목표

- run 하나의 공정 trace로 그 run의 Ex-situ 측정값을 예측한다: 두께 평균(Å), 웨이퍼 안 균일도 U/F(%), 웨이퍼 간 균일도 WtoW(%).
- 쓰임새: 측정 전에 두께가 벗어난 run을 미리 알아채고, 측정 빈도를 줄일 근거를 만든다.
- 판정 원칙은 가상 센서와 같다. PatchTST를 먼저 검증하고, 기준선 대비 seed 편차 2배를 넘게 나아질 때만 채택한다.
  안 되는 대상만 다른 모델로 푼다. LightGBM 등은 참고로 보인다.

## 지금까지 알고 있는 것

- 두께와 연결된 run은 49점 배치 run뿐이다. 이상 run 4개(통신 끊김, 두께가 크게 벗어난 run)를 빼면 학습 + 검증 run은 58개,
  시험 run 11개는 봉인한다(`configs/splits/split_v2.yaml`).
- 10-27 첫 확인(`configs/experiments/g2_thickness.yaml`, run 요약 특성 약 600개, leave-one-run-out, seed 1개):
  LightGBM만 학습 평균보다 나았다(MAE 두께 17%, U/F 17%, WtoW 29% 감소). Ridge · PLS는 학습 평균과 비슷하거나 못했다.
- run 간 두께 차이가 작다. 학습 평균 기준선의 MAE가 이미 작아서, 측정 잡음과 비슷한 크기일 수 있다.
- 사이클 수가 다른 두 run 묶음(초기 run과 이후 run)의 두께가 비슷하다. 원인은 아직 모른다.

## 핵심 질문

| 질문 | 왜 중요한가 | 확인 방법 |
|---|---|---|
| Q1. run 간 두께 차이가 측정 잡음보다 큰가 | 차이 대부분이 잡음이면 어떤 모델도 맞힐 수 없다. 모델 R²의 상한이 된다 | 측정점을 반씩 나눈 run 평균끼리의 상관(split-half 신뢰도) |
| Q2. 앞 run의 측정값이 다음 run을 얼마나 알려 주는가 | 운영에서 앞 run 측정값을 쓸 수 있으면, VM이 넘어야 할 기준선은 학습 평균이 아니라 EWMA다 | run 순서의 lag-1 상관, 학습 평균 · 이전 run 평균 · 바로 앞 run · EWMA의 MAE |
| Q3. 사이클 수, run 사이 대기 시간과 관계가 있는가 | 두께 = 사이클당 두께 × 사이클 수. 사이클당 두께가 무엇에 따라 바뀌는지가 특성 설계의 출발점 | 사이클 수별 사이클당 두께, 대기 시간과의 순위 상관 |
| Q4. 지금의 run 요약 특성 중 우연 수준을 넘는 것이 있는가 | 58개 run에 특성 600개면 우연히 높은 상관이 나온다 | 대상 순서를 섞었을 때 나오는 최대 상관(95% 분위)과 비교 |

## 단계

### 0단계: 데이터 점검 (학습 없음, `scripts/vm_audit.py`)

Q1~Q4를 학습 + 검증 run에서만 확인한다 → `work/reports/vm_audit.txt`. 이 결과로 1단계의 대상과 기준선을 정한다.

- 두께 평균의 split-half 신뢰도가 낮으면(0.5 미만) 두께 평균은 상한이 낮다. WAP별 두께, 중심 대 가장자리처럼 측정점이 많이 들어가는 대상을 앞에 둔다.
- EWMA가 학습 평균보다 확실히 나으면 기준선을 EWMA로 두고, VM은 앞 run 측정값을 입력으로 쓰는 경우와 쓰지 않는 경우를 따로 평가한다.
- 우연 수준을 넘는 특성이 없으면 특성 설계(1단계)를 먼저 하고 모델 탐색은 미룬다.

### 1단계: 특성 정리와 고전 모델 (CPU, 수 분)

- 신호별 요약 600여 개 대신 물리 근거가 있는 run 특성 수십 개로 줄인다.
  - 사이클 수, 사이클별 DCS 공급량(유량 × 시간), NH3 공급량, RF 켜진 시간과 전력 적분
  - 사이클 중 zone별 온도, DCS 공급 step의 압력 최고값, step 실제 길이(학습 run의 중앙값 대비)
  - 공정 전 대기 시간, 승온 안정화 시간
  - 가상 센서 결과 재사용: 가상 센서 추정과 실측의 차이를 run 단위로 요약한 "평소와 다른 정도"
- 모델: 학습 평균, EWMA, Ridge, PLS, LightGBM. 확률 요소가 있는 모델은 seed 3개.
- 평가: leave-one-run-out과 시간순 3구간(앞 run으로 학습, 다음 run 묶음으로 평가). 특성 선택도 교차검증 안에서 한다.

### 2단계: PatchTST (GPU)

- (a) 사이클 window 다중 사례 학습: run의 사이클마다 window를 잘라 모두 그 run의 두께를 정답으로 학습하고,
  run 예측은 사이클 예측의 평균으로 낸다. run마다 사이클이 많아 표본이 늘어나지만, 같은 run의 window는
  정답이 같으므로 분할은 반드시 run 단위로 한다.
- (b) 고정 encoder: 이미 학습한 가상 센서 · 미래값 PatchTST의 encoder로 사이클별 표현을 뽑아 run 평균을 내고,
  Ridge로 두께를 맞힌다. 새로 학습하는 것은 Ridge뿐이라 표본이 적어도 과적합이 덜하다.
- 판정: 기준선 대비 seed 편차 2배. 1단계 고전 모델과의 차이는 참고로 보인다.

### 3단계: 대상 넓히기

- WAP별 두께(boat 위치 5곳): run당 표본 5개. 위치를 특성으로 넣고, 평균과 WtoW는 위치별 예측에서 다시 계산한다.
- 중심 대 가장자리 두께: U/F가 어디서 생기는지(가장자리가 두꺼운지 얇은지) 설명한다.

## 누설 방지

- 분할은 run 단위. 정규화 값과 특성 선택은 학습 run에서만 정한다.
- EWMA와 앞 run 측정값은 평가 run보다 앞선 run만 쓴다.
- 시험 run은 최종 후보에서 한 번만 연다(`ald-final-test`). 데이터 점검(0단계)도 학습 + 검증 run만 본다.

## 공개 범위

- 두께 · U/F 값과 공정 조건은 공개 저장소에 올리지 않는다. README에는 기준선 대비 비율(개선율, 남은 오차)과 신뢰도 같은
  단위 없는 값만 적고, 계산 방식을 함께 적는다.
